# 新しい研究ページの制作基準

2026-09-05作成。研究室内で原稿と素材を準備し、Researchへ掲載するための基準。
文章の基準は [hero.txt](../hero.txt) と [サイトの用語集](README.md#言葉の整理2026-09-05-決定) に従う。
画像比率・レイアウトの数値は初期値であり、代表研究のページ見本で調整する。分類名は検討中のため固定しない。

## 1. 一つのページで伝えること

**何を対象に、どこを工夫し、何を確かめ、それが人に何を可能にするかを伝える。**

- 一つの研究テーマ・システムを一つのページにまとめる。同じ研究の続報や論文は、原則としてページを更新して追加する。独立した対象や成果がある場合は別ページにする。
- 同じ成果の再紹介、同じプロジェクトの発展、関連する並行研究を区別する。発展はページ内の研究項目として残し、直接の継承が確認できない研究を新旧版として扱わない。具体例は [研究紹介の統合案](../inventory/research-classification/consolidation.md) を参照。
- 専門外の学生や共同研究を考える人が冒頭を理解でき、専門家は結果と論文までたどれる構成にする。
- Physical AIを現在の重点として扱うが、すべての研究にその名称を付けない。材料・構造・センサ・回路・通信・計算のどこで問題を解いたかを具体的に書く。
- 「つくれる・直せる・選べる」「低消費電力」との関係は、研究で説明できる場合に書く。全ページに同じ理念文を繰り返さない。
- 発表済みの成果と、取り組んでいる目標を区別する。始まったばかりの研究は目的・方法・現在地を示せば掲載できる。成果の数で重要度を決めない。

## 2. ページの標準構成

| 順序 | 内容 | 原稿の目安・判断基準 |
|---|---|---|
| 1 | 研究名と一行説明 | 研究名だけで対象が分からない場合は補足する。一行説明は日本語40〜70字程度。誰に何ができるか、または何を実現する技術かを書く |
| 2 | 代表画像・必要なら動画 | 対象物、利用場面、実際の出力が分かるもの。タイトルと説明は画像の外に置く |
| 3 | 概要 | 日本語150〜250字程度。対象・従来の課題・工夫・確かめたことをまとめる |
| 4 | 設計上の工夫 | 2〜3節を目安に、写真や図と説明を組み合わせる。各節は一つの論点。見出しは「指先の力を制御に使う」のように具体的にする |
| 5 | 結果と現在地 | 何を、どの条件で確かめたか。比較対象、単位、試行条件、実機／シミュレーションを明示。未検証の用途は今後の目標として書く |
| 6 | 関連情報 | 著者・担当者、発表年、論文・DOI、公開しているコードや動画、共同研究先・助成情報、関連研究へのリンク |

短い研究は4・5をまとめてよい。内容のない節を作らず、必要な説明量で構成する。
助成情報は正式名称と当該研究との関係を確認して記載する。論文の採択・発表予定などの状態も正確に記す。

## 3. 一覧用画像と本文用画像を分ける

**一覧では研究を見分け、本文では仕組みと根拠を理解できるようにする。**

| 用途 | 初期値 | 選ぶ素材 |
|---|---|---|
| 一覧サムネイル | 4:3、原稿用の推奨書き出し1200×900px | 主題が一つの写真、出力例、簡潔な概要図。文字や細かい凡例なしでも対象が伝わるもの |
| 個別ページ冒頭 | 横長写真は16:9を第一候補、元画像は幅1600〜2400pxを目安 | 利用場面や装置全景。縦長写真や図は内容に合う比率を使い、無理に横長にしない |
| 本文の写真・図 | 元の比率を維持 | 仕組み、注目部分、比較、評価結果。一図一論点を基本にする |
| SNS共有画像 | 必要時に1200×630pxを別途用意 | 一覧用と同じ原本を使ってよいが、共有用の横長構図を確認する |

上記は研究室向けの初期値。TakramのProjects一覧は1200×630だが、その比率をそのまま採用するものではない。
解像度の低い原本を拡大して数値だけ満たさない。元画像を保存し、用途ごとに派生画像を作る。

### 選定とトリミング

- 写真は被写体に合わせて切り抜く。人の手、装置と対象の接触点、比較対象など、意味のある部分を残す。
- 図は全体を表示する。軸・凡例・矢印・比較条件を切らない。複合図を縮小して一覧に置かず、代表パネルか別の画像を選ぶ。
- 一覧用画像には長い説明や論文タイトルを焼き込まない。説明は画像の下に置く。
- 幅350px程度のスマホ表示で、何の画像か確認する。大きく開かないと対象が分からない場合は選び直す。
- 新規撮影では、全景・注目部分・使う場面を確保する。周囲に切り抜き調整用の余白を残す。
- 写真がない研究は、実際の出力、シミュレーション、概要図を使う。概念図や予測はその旨を明記し、未製作の装置を実物のように見せない。
- 画像にキャプションと代替テキストを用意する。キャプションは何を示すかと条件、代替テキストは画像の要点を伝える。

## 4. 動画の基準

動画は任意。把持・移動・変形など、動きが理解に必要な場合に使う。

- 一覧用は静止画を必須にする。注目研究の枠で動画を使う場合も、読み込み前や再生できない場合に同じ研究が分かる静止画を表示する。
- 短いプレビューは5〜10秒程度の無音ループを目安に、一つの動作を見せる。音声や字幕を読まなければ分からない説明は本文の動画に置く。
- 動作の最初から最後まで、対象と接触点が枠内に残ることを確認する。再生速度を変えた場合は明記する。
- 本文の説明動画は利用者が再生する。発話を含む場合は字幕または同内容の文章を用意する。
- 自動再生を実装する場合は、画面に近づいてから読み込み、画面外では停止する。動きを減らす設定では静止画にし、停止できる操作も用意する。
- 配信先と容量上限は実装時に決める。Vimeoの利用は必須ではない。長い高画質動画をそのままサムネイルとして読み込まない。

## 5. 文章・言語・分類

- 断定形を基本に、研究対象と使う人を具体的に書く。「革新的」「未来を変える」などの形容より、できたことと条件を示す。
- 問いかけ型の見出しや詩的なコピーは使わない。専門語は初出で短く説明する。研究名や正式な論文題名は正確に保つ。
- 日本語原稿を基準に、英語は段落ごとに翻訳する。片方だけ成果や説明を追加しない。日英は別ページにする。
- 図中の説明も各ページの言語に合わせた版を用意する。共通の記号・単位・固有名は維持する。翻訳図を作る場合は元の数値・対応関係を変えない。
- 分類は確定した領域定義に従い、対象と貢献から選ぶ。横断する場合は関連領域も記録する。現在検討中の4領域名を確定済みとして入力しない。
- 重点研究としての掲載位置と領域分類は別に判断する。無線給電やFabの比重変更だけを理由に、研究終了や過去の研究と表示しない。

## 6. 原稿と一緒に提出するもの

以下を一式で揃える。動画と公開コードなどは、存在する場合だけ提出する。

```text
研究名（日／英）：
一行説明（日／英）：
概要と本文（日／英、上記の標準構成）：
現在地（何を実証済みか／何に取り組んでいるか）：
担当者・著者、発表年：
分類候補と、その理由：
論文・DOI・発表状態：
共同研究先・助成情報：
関連研究・コード等のリンク：

一覧用静止画：
冒頭用画像（一覧用と共用する場合も明記）：
本文用の図・写真：
各画像の原本、キャプション・代替テキスト（日／英）：
各画像の切り抜き可否・残すべき部分、出典・クレジット：
動画（任意）：元動画、プレビュー用、静止画、速度変更の有無
```

これは原稿提出用の項目であり、Hugoのfront matter仕様ではない。既存の `pubs` や言語別メタデータとの対応はテンプレート実装時に整理する。

## 7. 公開前の確認

- [ ] 冒頭だけで、研究対象と工夫が分かる。
- [ ] 実証した結果・条件と、今後の目標が区別されている。
- [ ] 一覧用画像を明示的に選び、スマホでも主題が分かる。
- [ ] 写真の重要部分、図の軸・凡例、動画の動作が切れていない。
- [ ] 画像・動画を見られなくても、本文で主要な内容が分かる。
- [ ] 素材の出典・使用条件と必要なクレジットを確認した。
- [ ] 日英の説明・メタデータ・リンク先が対応し、人名と論文情報が正しい。
- [ ] PCとスマホで表示を確認し、画像の欠落・横はみ出し・壊れたリンクがない。

実装担当は配信画像のサイズ最適化、遅延読み込み、レイアウトの安定、動画の停止操作、Hugoビルドを確認する。
詳しい表示案と既存素材の比較は [画像運用案](../inventory/research-images/README.md) を参照。
