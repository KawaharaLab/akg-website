## 初回の導入（管理者が一度だけ）

1. 新シートを開き、「拡張機能 → Apps Script」を選ぶ。
2. 最初の `コード.gs` の内容を、同梱の `Code.gs` 全文で置き換えて保存する。他のプロジェクトのコードを上書きしない。
3. 関数一覧から `openManager` を選んで実行し、Googleの認可画面で権限と実行アカウントを確認する。
4. シートに戻る。以後、再読み込みすると「Publication管理 → 入力・編集画面を開く」が使える。

Webアプリとしてデプロイする必要はない。Google Sheetsの編集権限を持つ人が利用する。各利用者に初回認可が求められる場合がある。Apps Scriptで外部URL取得を使うため、管理ポリシーで制限されている場合は管理者による許可が必要。

接続ツールはGoogle Sheetsの作成・編集に対応するが、Apps Scriptの作成・コード配置には対応していないため、この初回操作は自動化できていない。

## 操作

- 新規登録、または題名・DOI・IDで既存レコードを検索する。
- DOI / 公開HTTPSの論文ページを入れて取得する。Crossref、DataCite、論文用HTMLメタデータに対応。取得できないページは手入力できる。
- 差分は既存値がある項目を初期選択しない。空欄補完だけ初期選択。利用者が選択した項目のみ入力欄に反映し、保存ボタンで書き込む。
- Crossrefのタイトル・サブタイトルを連結し、著者順序を保持する。査読・国際/国内・刊行状態は外部情報から推測して変更しない。
- 非公開の下書きは題名だけでも保存可能。公開には著者・採録先・業績種別、刊行状態、確認状態、グループ業績の対象判定が必要。暫定公開には確認担当メールも必要。
- DOI・巻号・ページの未確定は許容。次回確認日がなければ、将来の刊行予定月の翌月初日、または60日後を初期設定する。
- 「今回、内容を確認した」で最終確認日を記録。「次の確認を30日後にする」で再確認を延期できる。
- 同一DOI・同一正規化題名は警告する。別発表として必要なら明示的に確認して保存する。自動統合・削除はしない。
- グループ業績の対象と書誌情報の確認は別。別グループの業績は対象外として記録できる。
- 川原の登録漏れ候補検索はCrossrefの指定年・関連度順先頭100件に限り、著者がYoshihiro Kawaharaと完全一致するものを比較する。同姓同名、イニシャル表記、国内大会・DOI未登録等に限界があり、網羅的ではない。
- Fundingと研究のIDは各マスタに登録後、セミコロン区切りで指定。謝辞原文から助成課題を自動断定しない。

## 保存と運用上の範囲

- 保存時に行全体のハッシュを照合して競合を検出し、ドキュメントロックを使う。行位置ではなく固定IDで対象を探す。
- Google Sheetsの直接編集はロックの対象外なので、ハッシュ照合直後と書き込みの間の直接編集競合までは防げない。通常は入力画面から編集する。
- Apps Script経由の変更は変更履歴タブに記録。シート直接編集の履歴はGoogleの変更履歴で確認する。
- 原本タブと見出しは警告付き保護。管理者による編集自体を禁止するものではない。
- 保存はシート利用者の権限で実行し、公開API・認証情報はWebサイトに置かない。
- 通知は送信しない。担当者別のSlack/メール通知を導入する場合は送信先と頻度を決めて別途接続する。
- 出版社・Googleの取得制限、API障害、DOIの登録遅れで補完できない場合がある。保存済みの台帳を上書きせず、手入力で継続する。

## 確認事項の見方（2026-09-06更新）

確認事項タブを16列へ拡張。台帳の題名・著者・採録先・年月・DOI、外部の著者と題名、照合結果、重複相手の書誌を同じ行で確認できる。論文ページはDOIを優先し、なければ登録URLを参照する。台帳編集リンクは固定IDをMATCHして行を探すため、台帳の並べ替えに追従する。

285件の指摘・対応状況・確認メモは維持。対象241論文のうちDOI欄が埋まっていた172件を対象に、157個の異なるDOIからCrossrefの書誌取得を試行。157論文分で書誌取得、15論文分は取得未完了、69論文はDOI欄なし。著者の比較結果は候補であり、外部データ側の誤記・姓と名の区切り違いもある。題名が大きく違う場合は別論文・別版・翻訳題名を確認するまで著者の修正を保留する。

書誌表示と外部照合は今回取得時点のスナップショットで、自動再取得ではない。Publications本体の著者名は変更していない。
